A three-stop reference route

This is a reference route, not a record of a completed hands-on walkthrough.

  1. app/page.js — find analyze. It sends the current log, optional configuration and environment context to the API. Editing input clears stale results.
  2. lib/diagnose.js — find diagnose. It validates input, redacts secrets, selects rules or AI, checks the response and maps evidence numbers to actual log lines.
  3. app/page.js — find cause.evidence.map. A citation opens the sanitized preview at the referenced line.

To change this, start here

  • Colors and spacing: app/globals.css.
  • A new recognizable failure: lib/rules.js; add a realistic fixture and check the uncertainty boundary.
  • A new model adapter: lib/providers.js; preserve the validated output contract in lib/schema.js.
  • Assistant tools: mcp/server.js; reuse diagnose rather than duplicating logic.

A practice to reuse

Make uncertainty testable. The requirement “do not invent a cause from a timeout” becomes the timeout fixture and assertion in tests/diagnose.test.js. The missing-evidence result is a correct outcome. The same approach works whenever an AI feature must distinguish an observation from an inference.

Two bugs that verification caught

Browser requests exposed a mismatch between Next.js's internal URL and the incoming Host header. tests/http.test.js now checks that case. Review also found that trimming leading blank lines would shift evidence references; tests/diagnose.test.js preserves that invariant.

Run it again

npm ci, then npm run dev. Open 127.0.0.1:3000. Run npm test for service and MCP checks. Live AI needs server configuration; rules mode works immediately.
